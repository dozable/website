The dashboard on your other computers, tablets and phones (doz ui --lan)

doz ui is one dashboard. Without its LAN option it listens on 127.0.0.1 and nothing but this Mac can reach it.

doz ui is one dashboard. Without its LAN option it listens on 127.0.0.1 and nothing but this Mac can reach it. With the LAN option the SAME dashboard, on the same port, also serves the other browsers of your home network — the laptop on the couch, a second Mac, the iPad, a phone — at http://<this Mac>.local:7443.

Nothing listens beyond this Mac until you turn it on, and it is only ever turned on here, on the Mac (ui.lan cannot be changed from a browser). It runs until you press Ctrl-C (or run doz ui stop in another terminal). To keep it running without a terminal open, start it in the background:

A detached doz ui belongs to no terminal — closing the terminal does not stop it; its output goes to <store>/ui.log.

The earlier name of doz ui --lan, doz serve, still works for one release (it says so), and so do its subcommands (share, devices, revoke, rename, status, log and stop).

This Mac's browser and the others#

This Mac's browser is signed in by the link doz ui opens (or doz ui link), at http://127.0.0.1:<port>, as without the LAN option — and it can do everything, including typing a key and the windows on the Mac's screen (the folder pickers, Open in Terminal).

Every other browser gets in once, with an invite, and then stays in until you remove it. An invite is three things at once — use whichever suits the device:

  • a QR code — point a phone's or tablet's camera at it;
  • a short access code like Y14G-99K3 — type it on the dashboard's sign-in page;
  • a link — open it in the other browser.

Whichever is used first lets ONE browser in, within five minutes; the other two stop working. doz ui --lan prints an invite when it starts (on a terminal) — its link by name (http://<this Mac>.local:7443/…) and by each of the Mac's addresses (http://192.168.1.20:7443/…): .local names do not resolve the same everywhere, so use an address if the name does not answer. For another invite:

or, on any browser that is already in (this Mac's too): Devices › Add another browser.

Which kind of browser a request comes from is decided for each request: only a connection from this Mac itself, to 127.0.0.1:<port> exactly, with no reverse proxy in between, is this Mac's browser. The same Mac reaching the dashboard by <this Mac>.local or localhost is treated like any other browser (it needs an invite).

A browser that opens the dashboard without an invite sees the sign-in page and nothing else — no sandbox, no name, no data. A request the dashboard refuses always gets an answer saying why — only a sandbox's connection is dropped without one.

What another browser can do#

Everything the Mac's browser does — watch and drive sandboxes, open terminals in the browser, create sandboxes, change their network, settings, images and resources — with two exceptions:

  • No keys or tokens over plain HTTP. Adding an account's API key or setup token, a sandbox's own key or a GitHub token would send it across your network unencrypted, so the dashboard does not offer the field there and refuses it. Add it on the Mac (doz account add NAME --api-key, or this Mac's own browser), or reach the dashboard over HTTPS through your reverse proxy (below) — there it is allowed.
  • Nothing that opens a window on the Mac's screen: the Mac's folder and file pickers, Open in Terminal, Open folder and the Files tab's Open items are not shown on another computer. Type the folder's path instead, and use the browser's own terminals.

Chat is not shared with another browser unless you say so on the Mac: serve.chat is off (they do not see it), read (they read the rooms, with nothing they can send or change) or write (they also post, react, edit, delete, reveal and attach). A browser that may write acts as you in chat — the verified human whose words your agents act on — and each thing it sends is a line in doz ui log (never what it said). See Chat.

Workspaces and Agents / Bots are shown to another browser as to the Mac's own, except what is on this Mac's sessions: while serve.mac_sessions is off it does not see the loose sessions on this Mac, a workspace's agents on this Mac, the lines of its log about them, or who is working — Home, Loose agents and a workspace's page say how many were left out. A workspace's brief follows serve.chat, as its room does: off, the page says "the brief is not shared with this browser"; read, it is shown; write, it can also be edited (its announcement in the room speaks as you; each edit is a line in doz ui log, never the text). Another browser never makes, starts, stops, puts to sleep, wakes, finishes, archives, restores or deletes a workspace, adds or ends a worker or changes a bot, and never puts an agent in a workspace or takes one out — whatever serve.chat and serve.mac_sessions say, that is only the Mac's own browser (the New workspace wizard, Start, Sleep, Wake and the rest of a workspace's ⋯, Put in a workspace…, Add a worker, End…) or a terminal on the Mac (doz workspace new, start, sleep, wake, finish, archive, delete, adopt and release, doz worker add and end); another browser sees the wizard's and Add a worker's addresses as a notice and those buttons disabled, with the command instead. A workspace's Network & secrets, Folders & points, Activity and an agent's Can do are shown too, with the same rule for this Mac's sessions; another browser sees how many secrets each agent holds, never their names, cannot remove an ended session on this Mac (that is this Mac's own browser, or doz sessions @mac --forget-ended, whatever serve.mac_sessions says), and cannot allow a site for a session on this Mac (that is doz net allow @mac --session SESSION site:HOST on the Mac). The isolation guide is the same on every browser. See Sessions on this Mac.

Your Macs (the machine picker — "Dozable · studio ▾") is the same list on another browser as on this Mac: a phone switching between your Macs is what it is for. It holds names and addresses only; picking a Mac opens that Mac's own dashboard, where the browser needs that Mac's own invite. Adding or removing a Mac is done on this Mac, with doz ui macs.

ui.lan and the serve.* settings — who can reach the dashboard — are changed only on the Mac, with doz config set.

A workspace's runs can be listed from another browser, and a past run's messages read there only when serve.chat allows reading chat. Archiving or removing a room, and writing a run's archive again, happen only in this Mac's own browser (or with doz chat room … and doz workspace runs … in a terminal on the Mac).

Adding this Mac to another Mac's list#

To open this Mac's dashboard from another Mac's machine picker, put this dashboard on the network first (doz ui --lan, or doz ui publish tailscale), then, on the other Mac:

Give the address only — a sign-in link is refused and not kept. doz ui macs add checks once that this dashboard answers (doz ui macs check again later). Then pick studio in the other Mac's picker: a new tab opens this dashboard's sign-in page, and this Mac lets that browser in once with an invite, as any other (doz ui share here). See Your other Macs.

The browsers that are in#

The Devices page (on every browser that is in, and on this Mac's) lists the same, with Remove and Rename, and the recent activity. A removed browser is signed out at once — its pages say so and its terminals close — and needs a new invite to come back. A new link for this Mac's browser (doz ui link --rotate, doz ui --new-link) signs out this Mac's pages only; the other browsers stay in.

Every change another browser asks for, every terminal it opens, every admission and every refusal is written to an audit log — never a key, a code or what was typed:

Where it listens#

By default (serve.bind = lan) on every network interface of this Mac (Wi-Fi, Ethernet, the Thunderbolt Bridge) and on Tailscale — never on a sandbox's network. A sandbox can never reach the dashboard: a connection from a sandbox's network is dropped before anything is read, and the proxy that carries a proxied sandbox's traffic refuses the Mac's own addresses on the dashboard's port, whatever the sandbox's network policy says. This Mac's own browser is served at 127.0.0.1 whatever serve.bind says.

With the LAN option the dashboard announces itself with Bonjour as "Dozable on <this Mac>" (serve.advertise), so Safari's Bonjour list and other devices can find it.

The port is the dashboard's one port, ui.port. While ui.port is 0 (automatic), the LAN option uses serve.port (7443): with other browsers it never moves by itself — their sign-ins, an installed app and a bookmark belong to it. When another program holds it, doz ui refuses and names that program.

On your tailnet, at its own https address (Tailscale)#

If you use Tailscale, one command puts the dashboard on your tailnet at an address of its own, with a real certificate — so it can be installed as an app on your other devices and takes keys and tokens:

The first time, it shows Tailscale's sign-in link: open it, approve the new device, and the command carries on by itself (not approved within five minutes? run the same command again to continue). It then says the address, and the next step: run doz ui share on this Mac to let a browser on another device in, once — the address is on your tailnet only, and every browser still needs an invite.

What it does, in one step:

  • It runs Dozable's own Tailscale node, from Homebrew's tailscale (it does not need to be linked). The Mac's own Tailscale — the app or the tailscale command — is left exactly as it is. The node keeps its state in the store and is kept running by a LaunchAgent of yours, so it comes back after a restart.
  • It names the node dozable-<this Mac's local hostname> (--name chooses another).
  • Tailscale serves https://<name>.<your tailnet>.ts.net to the dashboard; plain http:// there redirects to it. The redirect answers on a second port of this Mac's, on 127.0.0.1 only, picked the first time and kept; nothing needs administrator rights.
  • It sets the dashboard up for it: a fixed ui.port, ui.lan on, serve.bind loopback, serve.public_origins the address and serve.trusted_proxies 127.0.0.1,::1 — then restarts the dashboard. Chat on other devices stays as serve.chat says.

Run it again any time: it re-applies everything (after you changed ui.port, say, or when doz doctor says plain http:// does not redirect — as it did for a dashboard published with version 0.51.14, where Tailscale refused the redirect). Check it:

Take it off again with doz ui unpublish tailscale — the dashboard is this Mac's only again (ui.port is kept). Add --logout to also sign the node out of your tailnet and remove its state; publishing again then asks you to sign in again, as a new device.

While it is published, the doz daemon keeps the dashboard running: it starts it in the background when the daemon starts (at login, with doz daemon login-item on) and again if it stops unexpectedly. doz ui stop is your word: after it the daemon leaves the dashboard stopped until you start it again (doz ui --detach). doz ui publish status says which.

HTTPS behind your own reverse proxy#

If you already run a reverse proxy at home (Caddy, Traefik, nginx, Nginx Proxy Manager, a Cloudflare Tunnel …), put the dashboard behind it: your proxy does HTTPS, and through it the dashboard can be installed as an app (with its offline page) and takes keys and tokens.

Tell doz ui three things:

For a proxy on another machine of your network, set serve.trusted_proxies to that machine's address and serve.bind to this Mac's address the proxy connects to (or leave it lan).

The dashboard believes X-Forwarded-Proto, X-Forwarded-Host and X-Forwarded-For ONLY from the addresses in serve.trusted_proxies; from anyone else they are ignored, and the public address is refused. A request that came through a proxy is never treated as this Mac's own browser, even from a proxy on this Mac. When it starts it prints the upstream your proxy should use and what is missing. Check the whole path:

— its dashboard via https://… line fetches each public address from this Mac and says whether it came back to this dashboard, over https, through a trusted proxy.

What your proxy must do: pass the Host header (or X-Forwarded-Host), set X-Forwarded-Proto and X-Forwarded-For, pass WebSocket upgrades (the terminals), and not buffer responses (the live updates are a server-sent event stream).

Caddy#

Caddy passes Host, sets the forwarded headers and upgrades WebSockets by itself; flush_interval -1 keeps the live updates unbuffered.

Traefik (file provider)#

Traefik passes Host and the forwarded headers and upgrades WebSockets by default.

nginx (and Nginx Proxy Manager's custom configuration)#

proxy_buffering off matters: with nginx's default buffering the live updates arrive late or not at all.

Cloudflare Tunnel#

cloudflared runs on this Mac, so serve.trusted_proxies is 127.0.0.1,::1 and serve.public_origins is https://doz.example.com. A tunnel puts the dashboard on the Internet: put Cloudflare Access in front of it too.

The Caddy and Traefik configurations above are the ones Dozable's own tests ran in front of the dashboard (terminals, live updates, the installable app, keys over https, doz doctor); the nginx and Cloudflare ones follow the same rules.

The macOS firewall and Local Network privacy#

  • Firewall (System Settings › Network › Firewall): when it is on, macOS asks once whether doz may accept incoming connections — answer Allow. A doz installed with Homebrew is signed, and with the firewall's "Automatically allow downloaded signed software" (on by default) it is allowed without asking. With "Block all incoming connections" nothing on your network can reach the dashboard; doz ui --lan says so when it starts. It never changes your firewall's settings.
  • Local Network privacy: accepting connections from your network needs no permission. Announcing with Bonjour is done on behalf of the app you run doz ui in (Terminal, iTerm2, your editor); if macOS has refused that app Local Network access, doz ui says it was not announced — browsers still reach it by address and by <this Mac>.local. To announce it: System Settings › Privacy & Security › Local Network, allow that app, or set serve.advertise to false.

Settings#

settingdefaultwhat
ui.lanfalseserve your other browsers too (--lan, --no-lan, $DOZ_UI_LAN)
ui.port0the dashboard's one port; 0 = automatic (--port, $DOZ_UI_PORT)
serve.port7443the port with the LAN option while ui.port is 0 ($DOZ_SERVE_PORT)
serve.bindlanlan, loopback, or this Mac's addresses (--bind, $DOZ_SERVE_BIND)
serve.public_origins—your proxy's https addresses
serve.trusted_proxies—your proxy's addresses or networks
serve.advertisetrueannounce with Bonjour
serve.mac_sessionsoffwhat these browsers may do with the sessions on this Mac: off, watch or interactive (Sessions on this Mac)
serve.chatoffwhat these browsers may do with chat: off, read or write — writing acts as you (Chat)

All of them but serve.mac_sessions and serve.chat (at once) apply when doz ui starts again (doz ui restart). See the Settings reference.
