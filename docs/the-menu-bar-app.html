Chapter 35

The menu bar app

Dozable's daemon is the background process that runs your sandboxes.

Dozable's daemon is the background process that runs your sandboxes. The menu bar app, Dozable.app, puts it in your Mac's menu bar: whether it is running, which version, how many sandboxes are up — and Start, Stop, Restart and Open Dashboard, one click each, and Start at Login. It has no chat and no settings of its own; everything else is doz and the dashboard.

It comes with doz (Homebrew and the release tarball carry it) and does nothing until you install it.

Install it#

This copies the app that came with your doz into /Applications (into ~/Applications when you cannot write to /Applications). Then open Dozable from Finder, Launchpad or Spotlight — or install and open in one go:

It has no Dock icon and no window: look for its icon in the menu bar, at the top right of the screen. It is signed and notarised by Dozable, so macOS opens it without a warning.

doz app install checks the copy before it installs it (its signature, that it is Dozable's, that it is the version of your doz) and then swaps it in whole — a copy that is already running keeps running the version it started with until you open it again. --dest DIR installs it somewhere else.

What the menu shows#

The first line is the daemon's state:

Daemon runs an older build (0.50.6) — Restart to updatedoz was upgraded while the daemon ran. Restart Daemon switches to the new version.

The icon is filled while the daemon runs, outlined when it is stopped, a warning triangle when a Restart is due, and hollow when there is no doz.

What it does#

  • Start Daemon — the same as doz daemon start.
  • Stop Daemon… — the same as doz daemon stop. When sandboxes are running it asks first: they hibernate, and wake when you use them again. Sessions on this Mac keep running.
  • Restart Daemon — the same as doz daemon restart: stop (sandboxes hibernate), then start on the current version.
  • Open Dashboard — the same as doz ui --detach --open: the dashboard opens in your browser, signed in. The sign-in link goes straight from doz to your browser; the app never sees it.
  • Start at Login — see below.
  • Quit Dozable Menu — quits the app only. The daemon and your sandboxes keep running.

The app runs doz for each of these, so it does exactly what the command does — including refusing what the command refuses (it shows doz's reason in the menu). It never starts the daemon just by looking: the state is read with doz daemon status, which never starts one.

The menu refreshes when you open it (and every two seconds while it is open), once a minute while it is closed, when your Mac wakes, and after every action.

Start at Login#

One switch for both: with Start at Login checked, the daemon starts when you log in (from your desktop session, so it can read your login Keychain) and the menu comes back too. Nothing is set up until you click it.

The first time, macOS shows a notice ("Login Item Added") and lists Dozable under System Settings › General › Login Items & Extensions. At login, and every 15 minutes after, the app runs the same short doz command doz's own login item runs: it starts the daemon if none runs (and you did not stop it), then exits. The daemon itself is never a login item.

the menu sayswhat it means
✓ Start at LoginOn. Click to turn it off (the daemon keeps running; it just will not start at your next login).
Start at LoginOff. Click to turn it on.
✓ Start at Login (set by doz — click to let this app hold it)doz's own login item starts the daemon (doz daemon login-item on). Click to let the app hold it instead: the app's item replaces doz's, and the menu comes back at login too.

Start at Login — needs doz 0.50.8Your doz is older than this needs. Upgrade doz (doz upgrade -y).

There is only ever one login item for the daemon: when the app holds it, doz removes its own, and doz daemon login-item says "the Dozable menu bar app starts the daemon at login". Turning Start at Login off, or removing the app (doz app uninstall), gives it back to you: doz daemon login-item on adds doz's own again. If you delete the app yourself without doz app uninstall, macOS may keep its login item listed (it does nothing without the app) — switch it off in System Settings; doz daemon login-item on works again either way.

Start at Login uses the default store (the one doz uses with no --store) and the doz installed by Homebrew or in ~/.local. A Dozable release runs only a doz signed by Dozable.

Updates#

The app updates with doz. After doz upgrade (or brew upgrade), the menu shows the new version and then offers Update Menu Bar App (old → new): it installs the copy that came with the new doz and reopens the app. When a newer copy is already installed but the old one is still running (after doz app install without --open), the menu offers Restart to Update (old → new) instead: it quits the running copy and opens the new one. Remove it#

This turns Start at Login off when it was on, quits the app and removes it from /Applications (and ~/Applications). The daemon keeps running. doz uninstall, which removes all of Dozable, removes the app too.

Where to look#

The app writes one line per doz command it runs to the system log — the command and its result, nothing else. To read it: log show --predicate 'subsystem == "com.dozable.app"' --last 1h.
