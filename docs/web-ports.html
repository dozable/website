Web ports: opening a sandbox's web page on your Mac

Some tools serve a web page from inside the sandbox: a chat playground, a workflow editor, the dev server of the app you are building.

On this page
  1. Where the ports come from
  2. When it listens
  3. What a forward can and cannot do

Some tools serve a web page from inside the sandbox: a chat playground, a workflow editor, the dev server of the app you are building. A forward makes such a port reachable in your Mac's browser, at http://127.0.0.1:PORT/ — on this Mac only, never on your network.

In the dashboard, a sandbox's header has an Open button for each web port while the sandbox runs, and its Overview tab lists every forward with its state.

Where the ports come from#

  • The tool's own. A tool whose recipe declares a web port gets it forwarded in every sandbox made from it — for example AIChat's playground (aichat --serve, port 8000, opened at /playground). Run the server in a session; its Open button works as soon as it listens.
  • Yours. doz ports add NAME PORT forwards any port a program you start listens on — a dev server, a notebook, a dashboard. --title names its button; --path is what doz open opens. At most 16 per sandbox.

When it listens#

A forward listens while the sandbox runs. When the sandbox stops, sleeps or hibernates, its listeners close at once; when it starts or wakes again — and after Dozable itself restarts — they come back by themselves. doz ports says stopped until then.

The port on your Mac is the sandbox's own when it is free. When another program on your Mac already uses it (or it is below 1024), Dozable picks a free one, says so (moved), and keeps it for next time.

What a forward can and cannot do#

  • This Mac only. It listens on 127.0.0.1 (and ::1), never on the network. Other programs on this Mac can reach it, as they can any local server — a tool with its own sign-in still asks for it.
  • Inbound only. It carries your browser's requests to the program in the sandbox. It does not let the sandbox reach anything: what the program itself may reach is still decided by the sandbox's network.
  • No key crosses it. Your keys are swapped in by Dozable's proxy only on the sandbox's own outbound requests; a forward never touches them. A page that shows its environment shows a placeholder, which is useless anywhere else.
  • From another device (the dashboard through doz serve), 127.0.0.1 is that device, not your Mac: the button says the port is on the Mac instead of opening it there.

How it works: each connection your browser makes is relayed into the sandbox by Dozable's small helper there, to the program's own localhost. A program that listens on 127.0.0.1 or 0.0.0.0 inside the sandbox both work.
