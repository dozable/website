Beside Claude Code, pi and Codex, Dozable runs agents from other makers. Each uses an API key — most of them of the provider or gateway you choose (--provider / --gateway, or the Quick try's “Where it gets its model”; --model picks the model; see Other AI tools). The key stays on your Mac and the sandbox only ever gets a placeholder, which Dozable's proxy swaps for the key on the way out — and only to that provider's or gateway's own API.

The first doz try of each asks for the key (a paste, or where you keep it: 1Password, AWS, a command — see Keys from 1Password, AWS or a command), prepares the agent's image once (a minute or so) and starts it. A try is Locked: the agent reaches its model and, below, the few hosts its maker's program calls when it starts — nothing else. Trying agents has the rest.

Antigravity CLI (Google)#

Google's terminal agent and the one to use with a Google key (doz try antigravity, or agy).

  • Installed from Google's own release for linux-arm64, checked against the SHA-512 Google publishes with it. Debian-based bases only for now (not Alpine). It is closed source; Dozable installs it from Google, it does not redistribute it.
  • Key: a Gemini API key (doz account add google --provider google; get one at https://aistudio.google.com/apikey). Dozable never offers the Google sign-in: it keeps its token in a keyring inside the machine.
  • Set up for you: approval prompts off (antigravity.permissions = ask keeps them), its updater off, its telemetry setting off.
  • Its first start is yours: it asks you to pick a colour scheme, then to accept Google's Terms of Service & Data Use — data sharing is ticked by default and you can untick it. Dozable never accepts those terms for you; doz try antigravity says so first, and so does the first step of its Guide.
  • May reach: the Gemini API (its model); Google's feature switches for it (antigravity-unleash.goog) when it starts; its usage log to play.googleapis.com, every few seconds. Its own telemetry setting does not stop that log, and Dozable allows it rather than blocking it.

Grok Build (xAI)#

xAI's own agent (doz try grok), on an xAI API key only: it checks its key with xAI's API when it starts and will not run without an xAI key or sign-in, so another provider's or gateway's key cannot stand in.

  • Installed from the npm registry's linux-arm64 package, integrity-checked. Debian, Node and Alpine bases.
  • Key: an xAI API key (doz account add xai --provider xai).
  • Set up for you: approval prompts off, its auto-updater off, its telemetry and feedback off; copying to your Mac's clipboard works (Dozable tells it the terminal takes OSC 52).
  • May reach: xAI's API (the paths Grok Build uses, and its key-less start-up check of api.x.ai/), and its release notes on x.ai when it starts.
  • Kept out, whatever you choose: xAI's sign-in hosts (Dozable never offers the sign-in).

OpenCode (open source)#

An open-source terminal agent that works with many model providers (doz try opencode). Dozable offers it on the key of the provider or gateway you choose: Anthropic, OpenAI, xAI (the default), Google AI, OpenRouter or Vercel AI Gateway; on xAI the model is xai/grok-build-0.1.

  • Installed from the npm registry's linux-arm64 package, integrity-checked. Debian and Node bases (not Alpine yet).
  • Key: an API key of that provider or gateway (doz account add NAME --provider xai — or openrouter, vercel-ai-gateway, google; --api-key for Anthropic, --openai-key for OpenAI); the sandbox only gets a placeholder.
  • No key at all (OpenCode 2): OpenCode Zen's free models — doz try opencode --provider opencode-zen, or OpenCode Zen in the try setup (marked "no key needed"). No account is used and nothing of yours is added to its requests. The model list shows each free model with its data terms as OpenCode's docs state them (some keep nothing, some are used to improve the model) — the free models OpenCode's docs list that this release of OpenCode can use without a key; doz models --provider opencode-zen lists them, and --model chooses one (default big-pickle). Only OpenCode's model requests to opencode.ai are allowed — not its Console or its sign-in. A key you add with OpenCode's own /connect is stored inside the sandbox; a key added in Dozable stays on your Mac.
  • Set up for you: its auto-update, session sharing, language-server downloads and the online model list off; the model set in ~/.config/opencode/opencode.json (written only when it is not there yet). Its plugin kit is not downloaded into ~/.config/opencode when it first starts (it is only for plugins you write; cd ~/.config/opencode && npm install @opencode-ai/plugin adds it). OpenCode asks no approval questions by default.
  • May reach: the API of the provider or gateway it was given (any of those it can use, so you can switch), and, for OpenCode 2, OpenCode Zen's model requests on opencode.ai (/zen/v1/chat/completions, /zen/v1/responses, and from OpenCode 2.0.32 /inference/openai/v1/chat/completions, /inference/openai/v1/responses).
  • Use: opencode (its TUI), or opencode run "…" for one answer.

GitHub Copilot CLI (GitHub)#

GitHub's terminal agent, run in its own bring-your-own-key mode (doz try copilot): it talks to your model with your key and never signs in to GitHub, so no Copilot plan is needed. Dozable points it at the provider or gateway you choose: Anthropic, OpenAI, xAI (the default), Google AI, OpenRouter or Vercel AI Gateway (on xAI the model is grok-code-fast-1).

  • Installed from the npm registry's linux-arm64 package, integrity-checked. Debian and Node bases (not Alpine yet). It is GitHub's software under its own licence; Dozable installs it from npm, it does not redistribute it.
  • Key: an API key of that provider or gateway (doz account add NAME --provider xai — or openrouter, vercel-ai-gateway, google; --api-key for Anthropic, --openai-key for OpenAI); the sandbox only gets a placeholder.
  • Set up for you: approval prompts off (--allow-all; copilot.permissions = ask keeps them), its offline mode (no GitHub sign-in, no calls to GitHub) and its auto-update off.
  • May reach: the API of the provider or gateway it was given (any of those it can use, so you can switch).

Qwen Code (Alibaba Qwen)#

Alibaba Qwen's open-source agent, a Gemini CLI fork (doz try qwen-code, or qwen). Its free Qwen sign-in ended in April 2026; Dozable runs it in its OpenAI-compatible mode, pointed at the provider or gateway you choose: OpenAI, xAI (the default), Google AI, OpenRouter or Vercel AI Gateway (--provider / --gateway, or the Quick try's “Where it gets its model”; --model picks the model). On xAI the model is grok-code-fast-1.

  • Installed from the npm registry, integrity-checked; it needs Node 22 (the Node and Debian bases; not Alpine).
  • Key: an API key of that provider or gateway; the sandbox gets a placeholder in its own variable and in OPENAI_API_KEY. Dozable sets OPENAI_BASE_URL and OPENAI_MODEL for the choice at each session.
  • Set up for you: approval prompts off (--approval-mode=yolo; qwen-code.permissions = ask keeps them), its auto-update and usage statistics off, and its download of the public model catalogue (models.dev) off — it uses the catalogue it ships with.
  • May reach: the API of the provider or gateway it was given (any of those it can use, so you can switch).

Factory Droid (Factory)#

Factory's terminal agent (doz try droid) in its airgap mode, on the key of the provider or gateway you choose: Anthropic, OpenAI, xAI (the default), Google AI, OpenRouter or Vercel AI Gateway — no Factory account, and none of Factory's servers. Droid takes it as a custom model, which Dozable sets in its settings at every run (on xAI, grok-build-0.1).

  • Installed from Factory's download server (its linux-arm64 build), checked against the SHA-512 Dozable recorded. Debian and Node bases (not Alpine: Factory publishes a glibc build only).
  • Key: an API key of that provider or gateway (doz account add NAME --provider xai — or openrouter, vercel-ai-gateway, google; --api-key for Anthropic, --openai-key for OpenAI); the sandbox only gets a placeholder.
  • Set up for you: airgap mode (FACTORY_AIRGAP_ENABLED=1): without it Droid calls Factory's API (sessions, usage, feature flags) and its telemetry even with your own model; with it, only the model. Its first start in a folder asks whether to trust it.
  • May reach: the API of the provider or gateway it was given (any of those it can use, so you can switch).
  • Use: droid (a session; with approvals off, --auto high), or droid exec -m "custom:$DOZ_MODEL" "…" for one task.

OpenHands CLI (OpenHands)#

OpenHands' terminal agent (doz try openhands). Its LLM settings come from the environment (--override-with-envs, in Dozable's command), set for the provider or gateway you choose: Anthropic, OpenAI, xAI (the default), Google AI, OpenRouter or Vercel AI Gateway (--provider / --gateway, or the Quick try's “Where it gets its model”; --model picks the model). On xAI the model is grok-build-0.1. Nothing is written to its settings.

  • Installed from its GitHub release (the linux-arm64 build), checked against the SHA-512 Dozable recorded. Debian and Node bases (not Alpine: OpenHands publishes a glibc build only).
  • Key: an API key of that provider or gateway (LLM_API_KEY and its own variable, the same placeholder in the sandbox). OpenHands Cloud's sign-in is not offered.
  • Set up for you: its model price list read locally (LITELLM_LOCAL_MODEL_COST_MAP, not fetched from GitHub) and its banner off.
  • May reach: the API of the provider or gateway it was given (any of those it can use), and two reads no setting turns off: its public skills (a git clone of github.com/OpenHands/extensions at each start) and its latest release on PyPI (a notice only; Dozable installs the pinned release).
  • Use: openhands (a session; with approvals off, --always-approve), or openhands --override-with-envs --headless -t "…" for one task.

CodeWhale#

A provider-neutral terminal agent, formerly DeepSeek TUI (doz try codewhale), on the key of the provider or gateway you choose: Anthropic, OpenAI, xAI (the default), Google AI or OpenRouter — its built-in providers (on xAI the model is grok-build-0.1; it has no Vercel AI Gateway provider).

  • Installed from its GitHub release (the static linux-arm64 build), checked against the SHA-512 Dozable recorded. Every base, Alpine included.
  • Key: an API key of that provider or gateway (doz account add NAME --provider xai — or openrouter, vercel-ai-gateway, google; --api-key for Anthropic, --openai-key for OpenAI); the sandbox only gets a placeholder.
  • Set up for you: its usage telemetry and update check off (CODEWHALE_TELEMETRY=0, CODEWHALE_NO_UPDATE_CHECK), its onboarding skipped. Its TUI refreshes the models.dev catalogue when it starts; Dozable keeps that out quietly, and it uses the catalogue it has.
  • May reach: the API of the provider or gateway it was given (any of those it can use, so you can switch).
  • Use: codewhale (a session; with approvals off, --approval-policy never), or codewhale exec "…" for one task (--auto lets it use tools).

Maki#

A Rust terminal agent with Lua plugins (doz try maki), on the key of the provider or gateway you choose: Anthropic, OpenAI, xAI (the default) or OpenRouter — its own providers, the model on its command line (on xAI, xai/grok-build-0.1).

  • Installed from its GitHub release (the static linux-arm64 build), checked against the SHA-512 Dozable recorded. Every base, Alpine included.
  • Key: an API key of that provider or gateway (doz account add NAME --provider xai — or openrouter, vercel-ai-gateway, google; --api-key for Anthropic, --openai-key for OpenAI); the sandbox only gets a placeholder.
  • May reach: the API of the provider or gateway it was given (any of those it can use, so you can switch), and GitHub's API for one read: its latest release, asked when its TUI starts. It also fetches the models.dev catalogue then; Dozable keeps that out quietly, and it does without it.
  • Use: maki (a session; with approvals off, --yolo), or maki -p "…" for one task.

oh-my-pi#

A batteries-included derivative of pi (doz try omp), on the key of the provider or gateway you choose: Anthropic, OpenAI, xAI (the default), Google AI, OpenRouter or Vercel AI Gateway — its built-in providers, the model on its command line (on xAI, xai/grok-build-0.1).

  • Installed from its GitHub release (the linux-arm64 build), checked against the SHA-512 Dozable recorded. Debian and Node bases (not Alpine yet).
  • Key: an API key of that provider or gateway (doz account add NAME --provider xai — or openrouter, vercel-ai-gateway, google; --api-key for Anthropic, --openai-key for OpenAI); the sandbox only gets a placeholder.
  • May reach: the API of the provider or gateway it was given (any of those it can use, so you can switch). When it starts it checks for a newer release and asks several model gateways for their public model lists (Kilo, Venice, ZenMux, Command Code, Charm Hyper, Alibaba Model Studio, a model catalogue); no setting turns that off, so Dozable keeps those requests out quietly, and it does without them.
  • Use: omp (a session), or omp -p "…" for one task.

Tau#

Hugging Face's Python port of pi (doz try tau), on the key of the provider or gateway you choose: Anthropic, OpenAI, xAI (the default), Google AI, OpenRouter or Vercel AI Gateway — its own providers, named on its command line (on xAI, grok-build-0.1).

  • Installed from PyPI into its own Python environment: Dozable's Python and exactly the packages Dozable locked, each checked against its recorded hash. Debian and Node bases (not Alpine yet).
  • Key: an API key of that provider or gateway (doz account add NAME --provider xai — or openrouter, vercel-ai-gateway, google; --api-key for Anthropic, --openai-key for OpenAI); the sandbox only gets a placeholder.
  • May reach: the API of the provider or gateway it was given (any of those it can use, so you can switch). Its update check and its model catalogue refresh are turned off.
  • Use: tau (a session), or tau -p "…" for one task.

Gemini CLI (Google) — superseded#

Superseded by Antigravity CLI: Google retired Gemini CLI for personal accounts; it still works with a paid Gemini API key. Dozable keeps it, listed after the current agents; doz try gemini says so first.

  • Installed from the npm registry, integrity-checked. Node, Debian and Alpine (on Alpine its shell tool runs without a terminal).
  • Key: a Gemini API key, as Antigravity CLI. Never the Google sign-in (Google's terms forbid third-party tools from using it).
  • Set up for you: approval prompts off, usage statistics off, auto-update off.

Coming: CodeBuddy Code, Every Code#

Two agents Dozable had recipes for are coming again, because their first screen is a sign-in Dozable cannot offer (doz search says why):

  • CodeBuddy Code (Tencent) asks you to sign in to a CodeBuddy account at its first screen, even with Dozable's model set.
  • Every Code (just-every, a Codex CLI fork) shows a ChatGPT sign-in whenever it has no login file, whatever provider is set.

Each comes back when it can start on the model Dozable gives it.

What each one calls — the network profiles#

Dozable keeps a network profile of every agent: a fresh try with the network open and every request logged, its first start and a short task, and for each host and path it called, a decision — allowed (and why), allowed by its path only, turned off by the agent's own setting, or refused. The recipes are checked against these profiles on every build, so an agent never meets a refusal on a normal first run, and a new release is profiled again before anything new is allowed (make profile-agents in the source tree; make agent-currency says which agents moved).

Is it current?#

doz search, doz try and the Quick try show each agent's latest release as your Mac last saw it — the version, the day it came out, how long ago, and active (a release in the last 3 months), quiet (none for 3), stale (none for 6) or deprecated by its maker — and its standing: current, or superseded by another agent. See Is it current?.
