History and retention

Dozable keeps a history of what happened on this Mac — every action on a sandbox, sessions, the daemon's runs and its events, each sandbox's connections and network by minute, CPU, memory and disk samples, the use of your keys (by name), workspace and permission logs, runs and their frames, and the times of chat messages and the outcomes of Asks — and answers it as one timeline: doz timeline.

Dozable keeps a history of what happened on this Mac — every action on a sandbox, sessions, the daemon's runs and its events, each sandbox's connections and network by minute, CPU, memory and disk samples, the use of your keys (by name), workspace and permission logs, runs and their frames, and the times of chat messages and the outcomes of Asks — and answers it as one timeline: doz timeline.

Nothing of it leaves your Mac. It lives in your store, readable only by you. No message text, Ask question, command line, path, URL, query string, header or key value is ever kept in it. The hosts a sandbox connected to are kept only as hidden details: they are never searched as text, never in a summary, and only shown when you ask for them by name (attr.dest:).

Looking at it#

Looking never starts the daemon: with none running, doz timeline answers from the store. The history is filled by the daemon as things happen; the first time it starts after an update, it reads everything already recorded in the background, and answers say "indexing … %" until it is done.

This Mac's name in the history is the setting daemon.mac_name, "this Mac" by default — a name you choose, never the Mac's network name:

How long each kind is kept#

Each source has a setting, timeline.SOURCE, with four parts in days: single events, then counts by minute, by hour and by day. kept keeps it until you delete it; each part is at least a day.

SettingDefaultWhat
timeline.actions30/30/365/keptactions on sandboxes (start, sleep, wake, …)
timeline.sessions30/30/365/keptsessions opened and ended
timeline.daemon30/30/365/keptthe daemon's runs
timeline.network30/30/365/keptconnections and bytes per sandbox per minute
timeline.workspace90/90/365/keptworkspace logs
timeline.grants365/365/365/keptpermission decisions and grants
timeline.runskept/kept/kept/kepta workspace's runs and a space's frames
timeline.chat30/30/365/keptchat message times and Ask outcomes
timeline.daemon_events7/30/365/keptthe daemon's own events
timeline.egress7/7/90/365each connection: its host is kept 7 days; counts per sandbox (never a host) longer
timeline.resources7/7/365/keptCPU, memory and disk samples
timeline.keys30/30/365/keptyour keys' use, by name

Counts are kept before single events go, so a zoomed-out timeline still shows the time; before a source's "since" it shows "not kept", never quiet time. How often samples are taken is timeline.sample_seconds (60; 0 = never); they are read from this Mac's side, never by running anything in the sandbox.

What is not bounded yet. These settings bound the history file and the records the history added (the daemon's events, each connection, samples, key use). Dozable's older records — the metrics of actions, sessions, daemon runs and the network, the workspace and permission logs — are not trimmed by them yet: they keep growing as before. You can clear the metrics in Resources (see Resources and disk space).

Starting the history again#

The history file (timeline.sqlite) is made from the records, so deleting it — in Resources, or with --clean — loses only the counts kept for time whose records are already gone.
