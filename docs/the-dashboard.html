The dashboard (doz ui)

doz ui is Dozable in your browser: every sandbox with a live terminal, its restore points and permissions, your images, accounts, disk use and settings.

doz ui is Dozable in your browser: every sandbox with a live terminal, its restore points and permissions, your images, accounts, disk use and settings. It does almost everything the command line does, and a few things are easier there — watching many sessions at once, or seeing what an agent was refused and allowing it with one click. It runs on your Mac only; nothing else can reach it.

Concepts#

  • One dashboard per store. Running doz ui again reuses the one that runs.
  • A one-use sign-in link. doz ui opens your browser with a link that works once, for five minutes, and signs that browser in — it stays signed in until you sign out or don't use it for 14 days (each visit renews it), so an installed dashboard app opens signed in. Nobody else can sign in without a link.
  • An app, if you like. Install it from Chrome or Safari and it opens in its own window with its own icon (see Install it as an app).
  • A client of the host, like the command line. Opening the dashboard doesn't start the host; any action you take does, as a command would.

Start it#

Stop it with Ctrl-C in its terminal, or doz ui stop from any terminal. doz ui --detach keeps it running without a terminal (its log is the file ui.log in the store) until doz ui stop; doz ui restart keeps it in the background. The address is http://127.0.0.1:PORT — this Mac only. The port is the setting ui.port: 0 (the default) means the port this store's last dashboard used, when it's free, so a page left open reconnects by itself — still signed in — when you start doz ui again, and no new tab opens. If another program took that port, doz ui says which and listens elsewhere. For an installed app, fix the port, because an app belongs to one address:

A fixed port that another program holds is never silently swapped: doz ui refuses to start and names the program. After doz ui restart onto a new port, the dashboard opens there in a new tab and the old page says where it went (a browser rule keeps a page from following by itself).

When a tab opens: only when none of the dashboard's pages is open (the setting ui.open_browser: auto). Set it to always or never, or use --open / --no-open for one run.

Treat a printed link like a password: anyone with it can sign in to your dashboard for those five minutes.

Install it as an app#

  • Chrome (or Edge): on the dashboard, the address bar's install icon or ⋮ › Cast, save and share › Install page as app… — Install Dozable. It opens in its own window, with the Dozable icon in the Dock and in ⌘-Tab, and shares Chrome's sign-in.
  • Safari: File › Add to Dock. A Safari web app keeps its own cookies, so it opens on the dashboard's sign-in: paste a link from doz ui link --print-url into its field.

When doz ui isn't running, the app (or a reload) shows Dozable isn't running on this Mac with what to run, instead of the browser's error page; it comes back by itself, on the view it was on, as soon as doz ui answers. The app needs nothing to stay running in the background.

The pages#

The sidebar starts with the menu button, the Dozable mark, its name and the store it shows. The top right corner of the window is where notifications appear (see Notifications). Each page's title stays at the top as the page scrolls, and a table's column headings stay under it. The sidebar groups the pages under five headings — Sandboxes (All sessions, All sandboxes and each sandbox), Recipes (Installed, Browse, Quick try — its + opens Quick try too), Store (Images, Resources), Activity (Operations, Activity, Metrics) and Setup (Accounts & keys, Settings, Devices, Doctor, Onboarding, Debug). The page, sandbox or session you are on is tinted, with a line at its left edge. Click All sandboxes while its page is shown (or its caret) to fold the list of sandboxes under it, and again to show it; this browser remembers. The menu button collapses the sidebar to a column of icons (hover one for its name) and expands it again; this browser remembers. In a window narrower than about 980 px the sidebar is always the column of icons, and the menu button shows the whole sidebar over the page. On a phone (narrower than about 760 px) the column goes too: a header row across the top holds the menu button, which opens the sidebar as a drawer, a key button while a key needs you, and + for Quick add.

Tick sandboxes in the left margin and the controls above the table — Start (start, resume or wake), Pause, Sleep, Hibernate, Shut down (asks first) — act on those; with none ticked they act on every sandbox, and each says how many it applies to. A cancelled one did nothing. One you start yourself on a single sandbox, or by typing in its terminal, goes ahead of them; a pause, and a resume from a pause, never wait. Under each sandbox, all its sessions (each with its agent's mark, or a terminal for a shell), in the order of the tabs on its page (then any without a tab: the agent's first), each with what it is doing; click one — or its screen icon — to open it; ⋮ (on hover) has Restart session and End session, and the screen icon beside it shows the session's live picture when you rest on it for half a second (then another session's line shows its picture at once). A sleeping sandbox lists the sessions it wakes back into. The caret beside a sandbox (or a click on the sandbox while its Home is shown) folds it to one line with its number of sessions (a session that needs you or failed still shows); this browser remembers the fold. ⋮ on the All sandboxes line (on hover) has Expand all and Collapse all.

A value set on this Mac, by the environment or by a flag has a bar at its left; Default puts this Mac's back. A recipe's own settings are on its page under Recipes. The search finds a setting by its key, its name, its section or a word of its description, across every section. When the page is wide enough, the sections are listed on the left (Access first), the one you are reading marked; a click jumps to it — narrower, the list is not shown. Folders on your Mac are never typed here: the projects folder has Choose…, your Mac's own folder picker; the others are set with doz config set. A new sandbox's permissions (defaults.permissions) are a table of what Locked, Standard and Open each allow, the current one marked, with the choice under it; Custom shows a switch for each permission. A sandbox's own values are on its page, Config › Settings (what it overrides, with Follow the Mac).

A sandbox's page#

  • The title row: the name, its state, and labelled facts — Image, RAM, Network (with how many connections were refused; click it for the Network tab), Account — and isolated or rules when they apply.
  • The toolbar: the state's actions as one group — led, for a sandbox that is shut down, paused, asleep or hibernated, by the action that brings it back (Start, Resume, Wake); Shut down apart, in red; ⋯ for Duplicate…, Save as template…, Boot log, then Reset… and Remove…. At its right: what is under way (or how the last action ended), and the button that shows or hides the details.
  • The terminals, whose tab strip carries what makes or arranges them: New Claude Code session (another session of the sandbox's own agent — claude-2, … — when it runs one), New shell (its ▾: Terminal…, Run detached…), Split (its ▾ picks what a split adds) and Open in Terminal. At the strip's left, the tabs menu (▾) lists every tab open here, with Close all tabs (the sessions keep running) and End all sessions…. The first tab is Home (below); then Console (the kernel and the guest's init, while the sandbox runs) and the sessions' tabs; the image's Build log opens in a tab of its own from Home › Logs. Start on the page opens the agent too; a start from a row of All sandboxes only boots it — its Home then offers Start Claude Code (or the sandbox's agent).
  • Home — every session of the sandbox, in one place: the agent's session as a card (what it is doing, since when, which tab shows it, Open, End…, and ⋯ for Watch, Open in Terminal, Restart session), the other sessions as rows, each with a small picture of its screen (live while the sandbox runs and Home is shown — a session with a tab mirrors that tab, every one of them, however many; its saved screen while it sleeps), then Logs (Console, the build log, the boot logs) and the Folder. List | Grid shows the sessions as a list or as a grid of their live pictures. The tab shows how many sessions run. A running session's ✕ asks: End session (its program stops), Hide — keep running (the tab goes, the session goes on) or Cancel; a read-only view, a saved screen or a second tab on the same session just closes. Closing the agent's tab another way (the tabs menu's Close all tabs) brings you back to Home, which says the agent is still running — every time, until you click Don't say this again (the setting ui.explain_tab_close). Console can be closed at any time, even during a boot; it stays closed until the next Start (Home › Logs › Console opens it again).
  • The details, beside them in tabs: Overview (RAM, disk, CPUs, the attach command, the workspace and its rules, its sessions and last restore point), Points (restore points), Network (What the agent can do, the rules, the connection log), Keys (keys and account) and Config (its configuration and the agent's environment prompt). The tab you chose is kept for each sandbox while the page is open; drag the details' left edge to widen them (320–560 px). Below about 760 px they move under the terminals.

Safety catches#

Reset, Remove, Revert and every delete ask you to tick a box first ("Yes, remove …"). Shut down asks with a plain confirmation. Clicking an action again while it runs does nothing more.

When something fails#

A failure is said where you started it, and stays until you dismiss it or it is put right: in the dialog (which stays open), on the sandbox's toolbar or its row on All sandboxes, in the step of a wizard, in the setting's row — or, when it has no place on the page you are on, at the top of the page. The brief messages at the bottom right only ever say that something worked. Operations keeps every action's result either way.

Keyboard#

Every control shows a ring when it has the keyboard's focus. Arrow keys move within tabs, segmented choices and menus; Escape closes a menu or a dialog. Three page shortcuts: g then s opens All sandboxes, / the Settings filter, ? the list of shortcuts. None of them works while a terminal has the focus — there every key is the terminal's.

The host, watched#

The status bar at the foot of the sidebar (it stays there as the sidebar's pages scroll; the sidebar's head stays at its top) starts with a dot for the dashboard's connection and one for the host, then the version, or what is wrong. Point at it for its card; click (or tap) it to keep the card open. The card has:

  • doz ui — the dashboard's connection.
  • host — whether the host runs, and its version, with Restart (it asks first, hibernates what runs — sessions kept, they wake when you use them — and starts the host again, as doz host restart does) or Start while none runs.
  • A line when the host and the dashboard are different versions, saying which is older: an older host is fixed by Restart; an older dashboard by doz ui restart.
  • updates — what the last check found (a newer doz and the command that installs it, or up to date, and when it was checked), with Check to look now. A doz built from source is never updated, and says so.

Notifications tell you what happened to the host:

  • The host stopped (doz host stop, idle, or a clean quit): your sandboxes were hibernated, with Start host.
  • The host crashed or was killed: the sandboxes that were running (they are shut down; start them again).
  • Another version of the host took over: it says so. If the host is older than the dashboard, Restart host asks first, hibernates what runs and starts the newer host (sandboxes wake when you use them). If the dashboard is the older one, restart doz ui.

Notifications#

Everything the dashboard tells you appears in the top right corner: a success (it goes by itself after a few seconds), a failure or a warning that has no closer place (it stays until you close it, or until it is no longer true), and the news about the host and the dashboard itself. The setting ui.notifications (Settings › This UI) chooses how they look:

  • Cards (the default) — a bell in the corner with the count, and a column hanging below it, the newest on top, each with its full text and buttons. A success has a strip along its foot counting down the seconds it has left. Point at any card and every countdown waits, and the column turns solid with Dismiss all; move away and they go on from where they were. Click the bell to hide the cards, and again to show them; a new notification shows them again. With none showing, the bell opens an empty column with the History link.
  • Pills — one line each along the top, the newest at the right; the ones that don't fit fold into +N. Click a pill for its full text and buttons.
  • Bell — a count; the newest shows beside it for a few seconds. Click the bell for the list, with Clear all.

Notifications (in the sidebar, under Activity) is the history: every notification this tab has shown, newest first, with the time — the ones showing now with Dismiss, and for the others how they ended (dismissed, went by itself, no longer true). Filter it by Showing, Failures, Warnings or Successes; Clear history forgets the ended ones. It lasts until the tab is closed.

The Debug page (in the sidebar, under Setup) makes each kind of notification with sample words, so you can see how each looks in each style. Nothing on it asks the host or changes a sandbox.

When doz ui restarts or stops#

A restart is routine — an upgrade, doz ui restart, the Mac waking up. For the first seconds the page says, calmly, Reconnecting to Dozable…; nothing behind it can be clicked meanwhile. When doz ui answers again the page carries on where it was, still signed in, with no reload:

  • Terminals reattach by themselves, with their screens (what you typed while it was away is dropped, never typed later). An open New sandbox wizard keeps its choices.
  • An operation that was running (a start, a wake) ends with what happened — the host carried it on — "finished while doz ui restarted", never a spinner that never stops.
  • A newer doz ui (after brew upgrade doz and a restart): a notification says Dozable was updated with Reload; the page reloads by itself as soon as nothing would be lost (no wizard or dialog open, no terminal you're typing in, nothing typed in a field).

If doz ui was stopped (Ctrl-C), or doesn't come back within 15 seconds, the overlay says what to run, when it was last connected and whether the host was running, with Try now; after a minute it adds the port the page expected. The page retries every second and comes back by itself when you start doz ui again (it says "doz ui restarted").

When the page must sign in again — after doz ui --new-link / doz ui link --rotate, after 14 days unused, or when you signed out — it says why and asks for a link inside the page: paste one from doz ui link --print-url (or open one with doz ui link). Everything on the page stays as it was while you sign in; its terminals reattach afterwards.

Terminals in the browser#

On a sandbox's page, a session's Open (on its Home) attaches to it and Watch (its ⋯) shows it read-only; on the terminals' tab strip New shell starts a new shell (shell-2, shell-3, …) and its ▾ › Terminal… starts a new session — a shell or one running a command. Terminals are tabs; Split shows two side by side. A running session's ✕ asks whether to End it or Hide its tab and keep it running. Each tab is titled like 1 · my-app · claude · 14:05 (the setting ui.terminal_title). Details, including the mouse, paste and the clipboard, in Terminals and sessions.

Open in Terminal opens the same session in your terminal app instead, via doz attach.

Open folder (the folder icon beside it) opens the sandbox's shared workspace on your Mac — Show in the Finder, or Open in &lt;editor&gt; for each editor installed (VS Code, Cursor, Zed, …; the one you used last first). An isolated sandbox has nothing on the Mac: the button says so. The same as doz files open NAME --app EDITOR (Terminals and sessions).

Keys in the browser#

With ui.allow_secret_entry on (the default), the wizard and Accounts & keys take an API key or setup token in a masked field, sent once and stored exactly as doz account add stores it. A sandbox's page can take a key of its own the same way. The dashboard never shows a secret: accounts and keys appear as a state, a source and a fingerprint. Turn it off with doz config set ui.allow_secret_entry false — the pages then show the commands instead. The dashboard can switch this off but never on.

Limits and security#

  • Loopback only unless you turn on its LAN option, and every page, request and terminal checks the sign-in cookie, the exact host and origin, and a CSRF token on every change. For the same dashboard on your other computers, tablets and phones, see doz ui --lan.
  • Terminals run in an isolated frame: whatever a sandbox prints can never reach your dashboard session, its cookie or other terminals. Links in terminal output aren't clickable.
  • The dashboard alone never keeps an idle host running; an open terminal does, as doz attach does.

Troubleshooting#

symptomwhat to do
"Sign in with a new link"The link was used, expired, or every page was signed out: paste a link from doz ui link --print-url, or open one with doz ui link.
A terminal says "Disconnected"It was silent a long time, or it could not reattach: Reconnect. (After a restart or a sign-in it reattaches by itself.)
"Dozable moved to 127.0.0.1:…"ui.port changed and doz ui restarted there: use the tab it opened (an installed app: install it again from there).
The installed app shows "Dozable isn't running"Start doz ui; the window comes back by itself.
"ui.port is …, and … listens on 127.0.0.1:…"Another program holds the fixed port: stop it, or doz config set ui.port N (0 = automatic).
Two tabs open each timeSet ui.open_browser to auto (the default) or run doz ui --no-open.
Open in Terminal does nothingMake a terminal app the handler for .command files: Finder › Get Info on any .command file › Open with › Change All…
"the resources are missing"Reinstall: brew reinstall doz.
