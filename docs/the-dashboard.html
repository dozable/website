The dashboard (doz ui)

doz ui is Dozable in your browser: every sandbox with a live terminal, its restore points and permissions, your images, accounts, disk use and settings. It does almost everything the command line does, and a few things are easier there — watching many sessions at once, or seeing what an agent was refused and allowing it with one click. It runs on your Mac only; nothing else can reach it.

Concepts#

  • One dashboard per store. Running doz ui again reuses the one that runs.
  • A one-use sign-in link. doz ui opens your browser with a link that works once, for five minutes, and signs that browser in — it stays signed in until you sign out or don't use it for 14 days (each visit renews it), so an installed dashboard app opens signed in. Nobody else can sign in without a link.
  • An app, if you like. Install it from Chrome or Safari and it opens in its own window with its own icon (see Install it as an app).
  • A client of the daemon, like the command line. Opening the dashboard doesn't start the daemon; any action you take does, as a command would.

Start it#

Stop it with Ctrl-C in its terminal, or doz ui stop from any terminal. doz ui --detach keeps it running without a terminal (its log is the file ui.log in the store) until doz ui stop; doz ui restart keeps it in the background. The address is http://127.0.0.1:PORT — this Mac only. The port is the setting ui.port: 0 (the default) means the port this store's last dashboard used, when it's free, so a page left open reconnects by itself — still signed in — when you start doz ui again, and no new tab opens. If another program took that port, doz ui says which and listens elsewhere. For an installed app, fix the port, because an app belongs to one address:

A fixed port that another program holds is never silently swapped: doz ui refuses to start and names the program. After doz ui restart onto a new port, the dashboard opens there in a new tab and the old page says where it went (a browser rule keeps a page from following by itself).

After an upgrade. doz ui restart (and Restart dashboard on the page) always starts the doz installed now — after brew upgrade, the new version, even when the dashboard was started from the one before. A dashboard in the background with no page open restarts into a new doz by itself within a minute of the upgrade; with a page open it waits for you: the status card says the dashboard is older and offers Restart dashboard.

When a tab opens: only when none of the dashboard's pages is open (the setting ui.open_browser: auto). Set it to always or never, or use --open / --no-open for one run.

Treat a printed link like a password: anyone with it can sign in to your dashboard for those five minutes.

Install it as an app#

  • Chrome (or Edge): on the dashboard, the address bar's install icon or ⋮ › Cast, save and share › Install page as app… — Install Dozable – john-mac-studio (the app is named for its Mac: its local hostname, from System Settings › General › Sharing). It opens in its own window, with the Dozable icon in the Dock and in ⌘-Tab, and shares Chrome's sign-in. Each Mac's dashboard is its own app — install the one of each Mac you use (from another computer, with the LAN option) and the windows are titled apart.
  • Safari: File › Add to Dock. A Safari web app keeps its own cookies, so it opens on the dashboard's sign-in: paste a link from doz ui link --print-url into its field.

When doz ui isn't running, the app (or a reload) shows Dozable isn't running on this Mac with what to run, instead of the browser's error page; it comes back by itself, on the view it was on, as soon as doz ui answers. The app needs nothing to stay running in the background.

The pages#

The sidebar starts with the menu button, the Dozable mark, its name with this Mac's name, and the store it shows — that name is the machine picker (see Your other Macs). The top right corner of the window is where notifications appear (see Notifications). Each page's title stays at the top as the page scrolls, and a table's column headings stay under it. The sidebar has four parts, top to bottom: Home (your workspaces — the page the dashboard opens on), Chat (while chat is on), Agents / Bots (with how many there are), then Workspaces — one line per workspace; the heading itself opens the Workspaces page — and This Mac, which holds every page that every workspace shares: Overview, Sessions, Sandboxes (each sandbox under it), On this Mac, Loose agents, Templates (Installed, Browse, Quick try — its + opens Quick try too), Images, Accounts & keys, Resources, Devices, Logs (Operations, Activity, Notifications, Metrics), Doctor, Setup, Settings and Debug. The + beside the This Mac heading is Quick add. The page, sandbox or session you are on is tinted, with a line at its left edge.

A workspace's line in the sidebar shows its state as a dot (a ring while it is setting up), its name, and a caret. Its name opens the workspace's page at its Home (below, A workspace's page); the caret unfolds it into its rooms (# review, each opening that room on the workspace's Room tab) and its agents — a sandbox's opens the sandbox's page, a session on this Mac opens it under On this Mac, an agent elsewhere is its name only; every workspace shows a small picture of itself first (see The workspace drawn; ui.nav_thumbnails turns it off). Asleep workspaces fold into one line, Asleep (2), and finished and archived ones into Finished & archived (5); this browser remembers what you unfolded. Click Sandboxes while its page is shown (or its caret) to fold the list of sandboxes under it, and again to show it; this browser remembers. The menu button collapses the sidebar to a column of icons (hover one for its name) and expands it again; this browser remembers. In a window narrower than about 980 px the sidebar is always the column of icons, and the menu button shows the whole sidebar over the page. On a phone (narrower than about 760 px) the column goes too: a header row across the top holds the menu button, which opens the sidebar as a drawer, the machine picker, a key button while a key needs you, and + for Quick add.

Your other Macs (the machine picker)#

"Dozable · studio ▾" at the top of the sidebar — this Mac's name — is a button: it opens Your Macs. This Mac comes first (you are here), then each Mac you added with doz ui macs add NAME ADDRESS (its Tailscale name or LAN address — see Adding this Mac to another's list), then Add a Mac… and Manage…, which open This Mac › Your Macs. Each Mac shows a dot, its name, its address, plain HTTP when it is not https, and what the last check found: a filled dot and seen 3 min ago when a check in the last ten minutes found it, else a hollow dot and last seen 2 days ago or never checked; one that could not be reached says why, and the command that checks it again (doz ui macs check NAME). Picking one opens that Mac's own dashboard in a new tab — the same as typing its address: you sign in to it there with doz ui share on that Mac. Nothing of this Mac's goes with it: no key, cookie or sign-in link is ever passed, kept or shown, and this page never contacts the other Mac (whether it answers is checked only by doz ui macs add and doz ui macs check). Each Mac stays its own: its own daemon, workspaces, agents and keys. On a phone, the name in the header row opens the same list. Enter, Space or ↓ on the name opens it, the arrow keys move through it, Escape closes it; g then m opens it from anywhere.

A workspace's page#

A workspace's page opens on its Home (#/w/NAME; the sidebar's name and Home's row lead there); its room is the Room tab (#/w/NAME/room; Open room and a room's line in the sidebar lead there). The title row has its name, its state, who drives it, its manager (an unfenced one says acts as you), one button for what its state offers next — Start while it is setting up, Sleep while it runs, Wake when it is asleep, Reopen when it is finished, Restore when it is archived — and ⋯: Stop the manager, Sleep everything, Wake everything, Finish…, Archive… and Delete…, and what it still lacks. Each opens a dialog that shows what it would do to each agent (on a phone, a card each), what is kept and what goes with sizes, how many change at once and Show the command; finish asks once, archive and delete want the workspace's name typed, and Also free …: remove the sandboxes Dozable made for it and Also move the folders Dozable made for it to the Bin (your own folders are never moved) are never ticked for you. While it works the state reads sleeping… or waking…. Only this Mac's own browser does these (see Workspaces). Below are its tabs: Home, Room, Agents, Network & secrets, Folders & points, Activity and Runs work; Permissions and Settings are marked coming and say what they will hold.

Home shows the workspace at a glance, drawn with its live state across the page. A workspace a space file made is drawn from its file: click the picture (or Edit the space beside it) to open the file in the space editor, the whole window (see Editing a space in the dashboard). One made without a space file — with the wizard, doz workspace new, by adopting agents — is drawn from its record, as doz workspace doc NAME writes it; there is no file to edit, so the picture opens nothing, and the command beside it prints the document. Below it, cards, each heading a link to the tab that holds the whole of it: Needs you first, only when something waits — what it still lacks while it is setting up, with Start and doz workspace start NAME; an open ask in one of its rooms, with Answer in the room (asks are answered in the room); an agent that is blocked or ended in error —, then State and run (since when, the space file it came from and whether it is up, its other lifecycle buttons, Runs), Who (who drives it, its manager, its agents, + Worker), the room's last two messages, Recent activity (the log's last five lines), Folders and Network. Home follows what happens without being reloaded, and never counts as being in the room: a message that arrives while you are on Home stays unread.

Network & secrets answers "what can this workspace reach?": each agent's network and the sites beyond it, what it was refused lately — Allow for that agent, or For all that can be limited (an unfenced agent and one elsewhere cannot; the default for new workers does not change) —, this Mac's ports and the forwarded ones, the secrets held for its agents by name, where each goes and a fingerprint, and the accounts used. Nothing on it is a secret's value. Allowing a site for a session on this Mac is done only in this Mac's own browser. Folders & points lists each folder, the files changed in it since the work started (found without running anything there; it never says which agent changed a file) and each Sandbox agent's restore points, with Take a restore point. Activity is the workspace's log, newest first (Load older for more), with the operations this dashboard started for its agents (the last 50); show All, You, Agents, Lifecycle or Network. Each tab is read afresh when you open it. An agent's Can do (the Can do button on its screen) is its capability table: each row live or at the next start, an unfenced agent's acts as you, and last its Permissions (how many allow, ask and never — the counts doz permissions show W --agent A prints) and its Ceiling, read only.

The work — the brief — sits above the room: its text, its references (a link opens in a new tab), who wrote it and when, and how many times it was edited, above the room on the Room tab. It is open on the main room and one line on another room's; Fold and Open change that, and this browser remembers it for each workspace. Edit changes the brief and nothing else; once the work has started, saving posts it in the room as your message ("I edited the work:" and the new text). If the brief changed since you opened it (from a terminal, or another browser), the save is refused and nothing is written. A brief over about 15 KB is saved with doz workspace edit NAME --prompt-file FILE instead (the page shows the command). History lists the edits — when and how long — each after the start linking to its message in the room.

The room is the same as on the Chat page — its messages, the composer, reactions, edits, attachments — showing only this workspace's rooms (a strip of # labels; + room is not there yet). Each agent's name carries its place in the workspace — its role, its agent program, how it is isolated, its session (manager · Claude Code · fenced) — and an unfenced one acts as you. What doz workspace log says (the work started, the brief edited, a worker added) shows among the messages in grey, by time; it is never posted in the room. An address naming a room that is not this workspace's opens its main room and says so.

The side panel says who is here and in what: each agent with its state, its isolation (Sandbox, fenced, unfenced, elsewhere), a worker's task — each opens its screen in the workspace (below) — then In this room, the workspace's folders and its network. + Worker opens Add a worker (below). In a narrow window the panel is below the room. Every isolation chip — here, on the Agents tab, on an agent's screen and in Agents / Bots — opens the isolation guide (#/guide/isolation) at that choice: Sandbox, fenced on this Mac, unfenced on this Mac and elsewhere, in order of isolation, each with what it is for and not for and its commands.

Agents (#/w/NAME/agents) is one table of every agent of the workspace, whatever runs it: where it is (this Mac or elsewhere) and how it is isolated (Sandbox, fenced, unfenced — which says acts as you and "no proxy · no placeholders · no guard" — or elsewhere, "not run by Dozable · token only"), its state, its task, what it uses and what isolates it, who started it and when, Watch (or Open) and ⋯ (its screen, Open in Terminal, Restart, End… for a worker — ticked, its place kept —, Take out of the workspace… and Move to another workspace…). + Add a worker opens Add a worker (#/w/NAME/agents/new): the agent program, its name, the account it would use (shown, not chosen), its one task, its rooms, who it is (anonymous, or an Agent / Bot), where it is, and where it runs — a table of Sandbox, fenced, unfenced and cloud (later) side by side, fenced chosen unless the workspace's or the bot's default is Sandbox; unfenced is never chosen for you and needs the tick "It acts as you". Each field is checked as you type and a refusal shows beside it; Show the command gives doz worker add … to run in a terminal instead; Add and start adds it. A worker that ended is listed folded below; a greyed "cloud worker" row shows where a worker run off your Mac will appear later; Grid is coming. In a narrow window each agent is a card.

An agent's screen (#/w/NAME/agent/AGENT) is its sandbox's page, or its session's on this Mac, as you know them — the terminals, Home, the details — under the workspace's name: a line NAME › Agents › AGENT with its chips and Open the room beside and ⋯ (Add a worker…, and End… for a worker), and in the details' Overview In this workspace (its role, task, who started it and when, its isolation and rooms). Switching its tabs keeps that address. An agent with no screen here — one elsewhere, a manager not started, a sandbox or session that is gone — shows a card saying so (and, for one gone, Take out…). A sandbox's own page (#/sandbox/NAME) still opens as itself; for one in a workspace it says In NAME as AGENT — open it there.

The Workspaces page#

Workspaces (#/workspaces; click the Workspaces heading in the sidebar, or All workspaces → on Home) lists every workspace on this Mac, finished and archived ones too, as Rows or as a Grid of cards. Each shows its picture (a small tile for one made without a space file), its name (it opens its Home), its state, who drives it and its manager, who is working, its room (it opens the Room tab), how long ago its log last moved ("active 3 h ago") and its one next action. Show picks which — Every workspace, Waiting on you, Working, Idle, Setting up, Asleep, Finished & archived, each with how many —, and Sort orders them by State (as Home and the sidebar do), Name or Last activity. This browser remembers the layout and the sort; Show starts at every workspace each time.

#/sandbox/NAME, #/chat, #/new (New sandbox), #/onboarding and #/try are unchanged; #/new-workspace is the New workspace wizard (#/new-workspace?bot=NAME with that Agent / Bot chosen as its manager). A workspace's page is #/w/NAME (its Home; #/w/NAME/ and #/w/NAME/home lead there), its Room tab #/w/NAME/room (its main room) and #/w/NAME/room/LABEL (another of its rooms, by its short label); the Workspaces page is #/workspaces; its Agents tab is #/w/NAME/agents and an agent's screen #/w/NAME/agent/AGENT (with /SESSION for one of its sandbox's sessions). #/mac alone is now This Mac's overview (its first line leads to On this Mac), and a session on this Mac named like one of This Mac's pages (images, logs, …) is reached from On this Mac rather than by its old address.

A sandbox's page#

  • The title row: the name, its state, and labelled facts — Image, RAM, Network (with how many connections were refused; click it for the Network tab), Account — and isolated or rules when they apply.
  • The toolbar: the state's actions as one group — led, for a sandbox that is shut down, paused, asleep or hibernated, by the action that brings it back (Start, Resume, Wake); Shut down apart, in red; ⋯ for Duplicate…, Save disk as image…, Boot log, then Reset… and Remove…. At its right: what is under way (or how the last action ended), and the button that shows or hides the details.
  • The terminals, whose tab strip carries what makes or arranges them: New Claude Code session (another session of the sandbox's own agent — claude-2, … — when it runs one), New shell (its ▾: Terminal…, Run detached…), Split (its ▾ picks what a split adds) and Open in Terminal. At the strip's left, the tabs menu (▾) lists every tab open here, with Close all tabs (the sessions keep running) and End all sessions…. The first tab is Home (below); then Console (the kernel and the guest's init, while the sandbox runs) and the sessions' tabs; the image's Build log opens in a tab of its own from Home › Logs. Start on the page opens the agent too; a start from a row of Sandboxes only boots it — its Home then offers Start Claude Code (or the sandbox's agent).
  • Home — every session of the sandbox, in one place: the agent's session as a card (what it is doing, since when, which tab shows it, Open, End…, and ⋯ for Watch, Open in Terminal, Restart session), the other sessions as rows, each with a small picture of its screen (live while the sandbox runs and Home is shown — a session with a tab mirrors that tab, every one of them, however many; its saved screen while it sleeps), then Logs (Console, the build log, the boot logs) and the Folder. List | Grid shows the sessions as a list or as a grid of their live pictures. The tab shows how many sessions run. A running session's ✕ asks: End session (its program stops), Hide — keep running (the tab goes, the session goes on) or Cancel; a read-only view, a saved screen or a second tab on the same session just closes. Closing the agent's tab another way (the tabs menu's Close all tabs) brings you back to Home, which says the agent is still running — every time, until you click Don't say this again (the setting ui.explain_tab_close). Console can be closed at any time, even during a boot; it stays closed until the next Start (Home › Logs › Console opens it again).
  • The details, beside them in tabs: Overview (RAM, disk, CPUs, the attach command, the folder and its rules, its sessions and last restore point), Points (restore points), Network (What the agent can do, the rules, the connection log), Keys (keys and account) and Config (its configuration and the agent's environment prompt). The tab you chose is kept for each sandbox while the page is open; drag the details' left edge to widen them (320–560 px). Below about 760 px they move under the terminals.

Safety catches#

Reset, Remove, Revert and every delete ask you to tick a box first ("Yes, remove …"). Shut down asks with a plain confirmation. Clicking an action again while it runs does nothing more.

When something fails#

A failure is said where you started it, and stays until you dismiss it or it is put right: in the dialog (which stays open), on the sandbox's toolbar or its row on Sandboxes, in the step of a wizard, in the setting's row — or, when it has no place on the page you are on, at the top of the page. The brief messages at the bottom right only ever say that something worked. Operations keeps every action's result either way.

Keyboard#

Every control shows a ring when it has the keyboard's focus. Arrow keys move within tabs, segmented choices and menus; Escape closes a menu or a dialog. Five page shortcuts: g then h opens Home, g then s opens This Mac › Sandboxes, g then m opens Your Macs (the machine picker), / the Settings filter, ? the list of shortcuts. None of them works while a terminal has the focus — there every key is the terminal's.

A workspace's runs#

A workspace's Runs tab lists each run — each start or reopen to its finish — with its length, whether its archive was written and how big it is, and its totals. Read its messages opens a past run's chat from its archive, read-only, with its timesheet. Below, each of the workspace's rooms shows its state (open, closed, archived or gone). In this Mac's own browser, Archive room… and Remove room… put a finished workspace's room away and then remove it for good; Remove room… asks you to type the room's name. When a workspace is finished, its room's message box is off and says so; reopen the workspace to post again. The Finish dialog shows what becomes of each room and what the run's archive will hold, with Finish without an archive unticked.

The daemon, watched#

The status bar at the foot of the sidebar (it stays there as the sidebar's pages scroll; the sidebar's head stays at its top) starts with a dot for the dashboard's connection and one for the daemon, then the version, or what is wrong. Point at it for its card; click (or tap) it to keep the card open. The card has:

  • doz ui — the dashboard's connection.
  • daemon — whether the daemon runs, and its version, with Restart (it asks first, hibernates what runs — sessions kept, they wake when you use them — and starts the daemon again, as doz daemon restart does) or Start while none runs.
  • A line when the daemon and the dashboard are different versions, or a newer doz is installed than the dashboard runs, saying which is older: an older daemon is fixed by Restart; an older dashboard by Restart dashboard (in this Mac's own browser — another computer's page does not offer it) or doz ui restart. The page waits for the dashboard to come back and reloads itself.
  • updates — what the last check found (a newer doz and the command that installs it, or up to date, and when it was checked), with Check to look now. A doz built from source is never updated, and says so.

Notifications tell you what happened to the daemon:

  • The daemon stopped (doz daemon stop, idle, or a clean quit): your sandboxes were hibernated, with Start daemon.
  • The daemon crashed or was killed: the sandboxes that were running (they are shut down; start them again).
  • Another version of the daemon took over: it says so. If the daemon is older than the dashboard, Restart daemon asks first, hibernates what runs and starts the newer daemon (sandboxes wake when you use them). If the dashboard is the older one, Restart dashboard (or doz ui restart).

Notifications#

Everything the dashboard tells you appears in the top right corner: a success (it goes by itself after a few seconds), a failure or a warning that has no closer place (it stays until you close it, or until it is no longer true), and the news about the daemon and the dashboard itself. The setting ui.notifications (Settings › This UI) chooses how they look:

  • Cards (the default) — a bell in the corner with the count, and a column hanging below it, the newest on top, each with its full text and buttons. A success has a strip along its foot counting down the seconds it has left. Point at any card and every countdown waits, and the column turns solid with Dismiss all; move away and they go on from where they were. Click the bell to hide the cards, and again to show them; a new notification shows them again. With none showing, the bell opens an empty column with the History link.
  • Pills — one line each along the top, the newest at the right; the ones that don't fit fold into +N. Click a pill for its full text and buttons.
  • Bell — a count; the newest shows beside it for a few seconds. Click the bell for the list, with Clear all.

Notifications (in the sidebar, under Activity) is the history: every notification this tab has shown, newest first, with the time — the ones showing now with Dismiss, and for the others how they ended (dismissed, went by itself, no longer true). Filter it by Showing, Failures, Warnings or Successes; Clear history forgets the ended ones. It lasts until the tab is closed.

The Debug page (in the sidebar, under Setup) makes each kind of notification with sample words, so you can see how each looks in each style. Nothing on it asks the daemon or changes a sandbox.

When doz ui restarts or stops#

A restart is routine — an upgrade, doz ui restart, the Mac waking up. For the first seconds the page says, calmly, Reconnecting to Dozable…; nothing behind it can be clicked meanwhile. When doz ui answers again the page carries on where it was, still signed in, with no reload:

  • Terminals reattach by themselves, with their screens (what you typed while it was away is dropped, never typed later). An open New sandbox wizard keeps its choices.
  • An operation that was running (a start, a wake) ends with what happened — the daemon carried it on — "finished while doz ui restarted", never a spinner that never stops.
  • A newer doz ui (after brew upgrade doz and a restart): a notification says Dozable was updated with Reload; the page reloads by itself as soon as nothing would be lost (no wizard or dialog open, no terminal you're typing in, nothing typed in a field).

If doz ui was stopped (Ctrl-C), or doesn't come back within 15 seconds, the overlay says what to run, when it was last connected and whether the daemon was running, with Try now; after a minute it adds the port the page expected. The page retries every second and comes back by itself when you start doz ui again (it says "doz ui restarted").

When the page must sign in again — after doz ui --new-link / doz ui link --rotate, after 14 days unused, or when you signed out — it says why and asks for a link inside the page: paste one from doz ui link --print-url (or open one with doz ui link). Everything on the page stays as it was while you sign in; its terminals reattach afterwards.

Terminals in the browser#

On a sandbox's page, a session's Open (on its Home) attaches to it and Watch (its ⋯) shows it read-only; on the terminals' tab strip New shell starts a new shell (shell-2, shell-3, …) and its ▾ › Terminal… starts a new session — a shell or one running a command. Terminals are tabs; Split shows two side by side. A running session's ✕ asks whether to End it or Hide its tab and keep it running. Each tab is titled like 1 · my-app · claude · 14:05 (the setting ui.terminal_title). Details, including the mouse, paste and the clipboard, in Terminals and sessions.

Open in Terminal opens the same session in your terminal app instead, via doz attach.

Open folder (the folder icon beside it) opens the sandbox's shared folder on your Mac — Show in the Finder, or Open in &lt;editor&gt; for each editor installed (VS Code, Cursor, Zed, …; the one you used last first). An isolated sandbox has nothing on the Mac: the button says so. The same as doz files open NAME --app EDITOR (Terminals and sessions).

Keys in the browser#

With ui.allow_secret_entry on (the default), the wizard and Accounts & keys take an API key or setup token in a masked field, sent once and stored exactly as doz account add stores it. A sandbox's page can take a key of its own the same way. The dashboard never shows a secret: accounts and keys appear as a state, a source and a fingerprint. Turn it off with doz config set ui.allow_secret_entry false — the pages then show the commands instead. The dashboard can switch this off but never on.

Limits and security#

  • Loopback only unless you turn on its LAN option, and every page, request and terminal checks the sign-in cookie, the exact host and origin, and a CSRF token on every change. For the same dashboard on your other computers, tablets and phones, see doz ui --lan.
  • Terminals run in an isolated frame: whatever a sandbox prints can never reach your dashboard session, its cookie or other terminals. Links in terminal output aren't clickable.
  • The dashboard alone never keeps an idle daemon running; an open terminal does, as doz attach does.

Troubleshooting#

symptomwhat to do
"Sign in with a new link"The link was used, expired, or every page was signed out: paste a link from doz ui link --print-url, or open one with doz ui link.
A terminal says "Disconnected"It was silent a long time, or it could not reattach: Reconnect. (After a restart or a sign-in it reattaches by itself.)
"Dozable moved to 127.0.0.1:…"ui.port changed and doz ui restarted there: use the tab it opened (an installed app: install it again from there).
The installed app shows "Dozable isn't running"Start doz ui; the window comes back by itself.
"ui.port is …, and … listens on 127.0.0.1:…"Another program holds the fixed port: stop it, or doz config set ui.port N (0 = automatic).
Two tabs open each timeSet ui.open_browser to auto (the default) or run doz ui --no-open.
Open in Terminal does nothingMake a terminal app the handler for .command files: Finder › Get Info on any .command file › Open with › Change All…
"the resources are missing"Reinstall: brew reinstall doz.
