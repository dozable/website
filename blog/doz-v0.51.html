19 November 2026 Release news

Dozable 0.51 - chat rooms, and fenced sessions on your Mac

Dozable 0.51 adds chat rooms for you and your agents, fences sessions on your Mac by default, keeps the daemon running with a menu bar app, and can publish the dashboard on your tailnet.

It's on the stable channel now, as 0.51.15. This post covers 0.40.0 to 0.51.15; the 0.37 post covers what came before. The changes come first by theme, then release by release in the detailed changelog.

Chat rooms for you and your agents#

Chat is a set of rooms on your Mac where you and your agents talk: you in the dashboard or a terminal, each agent with its own token. It is off until you turn it on, it listens on this Mac only, and everything is kept in your store.

  • The Chat page in the dashboard has the rooms, messages as they arrive, @ mentions, reactions, edit and delete, direct messages and attachments up to 20 MB.
  • dozchat is a small chat client on the PATH of every sandbox and fenced session. Give it its token as a secret (below) and the session only ever sees a placeholder.
  • Claude Code sessions on this Mac can take part: the chat server writes each message into the session's own inbox, busy or idle (doz chat add bot1 --inbox). This works for sessions without a fence; a fenced one uses dozchat.
  • Webhook bots are called with each message instead of polling (doz chat webhook set NAME). The address and its secret are kept in your login keychain.
  • Agents on your other machines can join over Tailscale, as agents with their own token, never as you (chat.remote_listen and chat.remote_agents).
  • doz chat import brings in the history of another chat server from an export.
  • Your other browsers get no chat until you set serve.chat to read or write.

Sessions on this Mac are fenced#

In 0.37 a session on this Mac ran as you, with nothing around it. A new session is now fenced: macOS's own sandbox keeps it to its project folder, its own temporary files and caches, and Dozable's proxy for the network. Your Keychain, secrets and other folders are closed to it. --unfenced gives a session what it had before, and sessions you opened earlier keep their mode.

  • Claude Code in a fenced session gets its own settings folder and its login through the proxy, so it never holds your token. Its conversations come back to ~/.claude/projects when it ends.
  • Tools work through the fence: git and ssh, GitHub as you (--github read|push), your SSH agent (--ssh-agent), the package registries, Swift and Xcode builds (--xcode) and the Simulator (--simulator).
  • New session on this Mac… in the dashboard gives the exact command for five common setups, including the build commands that work inside the fence and when to go unfenced. Each session's What it can do tab shows its permissions and switches them live.
  • A service on your Mac, such as a local API, is reachable from a sandbox or session with --host-port 8790, as host.dozable.internal:8790. Nothing else of the Mac opens.
  • --secret gives a session a token as a placeholder, which Dozable swaps for the real value only on requests to the host and port you name.
  • Site permissions can name ports: doz net allow NAME site:example.com:8443.
  • Sandboxes can no longer reach this Mac through any of its network addresses.

The manual has the details: Sessions on this Mac.

The daemon stays running, with a menu bar app#

Dozable's background process is now called the daemon, and doz host is gone, with no alias:

  • It stays running (daemon.always_on, on by default), and when you upgrade it moves to the new version by itself once nothing is running.
  • It can start when you log in. Nothing is added until you ask: doz daemon login-item on.
  • The menu bar app shows the daemon's state, with Start, Stop, Restart, Open Dashboard and Start at Login: doz app install --open.
  • An unattended Mac keeps its Claude login. doz account keepalive always renews it when it expires.

The dashboard on your tailnet#

doz ui publish tailscale gives the dashboard its own https address, https://dozable-<your Mac>.<your tailnet>.ts.net, through a Tailscale node of Dozable's own; your Mac's own Tailscale is left alone. The address comes back after a restart of the Mac.

Each browser on another device still needs an invite (doz ui share). See The dashboard on your other devices.

The dashboard also follows upgrades now, and offers Restart dashboard when it is older than the doz you installed.

Detailed changelog#

Every release from 0.40.0 to 0.51.15, newest first. Stable marks the releases that reached the stable channel; the others were on canary only, and their changes reached stable with the next stable release. Numbers that are missing, such as 0.40.1, were never released.

0.51.15 - 18 November 2026 - stable#

  • Fixed: doz ui publish tailscale sets up the redirect from plain http:// to the https address on a real Mac. A dashboard published with 0.51.14 is told to run doz ui publish tailscale again.

0.51.14 - 18 November 2026#

  • Added: doz ui publish tailscale gives the dashboard its own https address on your tailnet, through Dozable's own Tailscale node (your Mac's own Tailscale is left alone). doz ui publish status and doz ui unpublish tailscale [--logout].
  • Added: while it is published, the daemon keeps the dashboard running, until you run doz ui stop.

0.51.13 - 18 November 2026 - stable#

  • Changed: the dashboard follows upgrades. doz ui starts the doz installed now, and a dashboard in the background restarts into a new doz when nothing is open.
  • Added: Restart dashboard in the dashboard when it is older than the installed doz (this Mac's own browser only).
  • Changed: the installable dashboard app is named after its Mac ("Dozable – <this Mac>"). A copy installed before may need installing again to pick up the name.
  • Fixed: doz doctor no longer tells you to stop a newer daemon when the dashboard is the older one, and an update is never offered for the build already installed.

0.51.12 - 18 November 2026 - stable#

  • Fixed: a fenced Claude Code session started as env NAME=VALUE … claude works, and resumes with its variables.
  • Changed: every fenced session gets its own temporary folder for Claude Code (CLAUDE_CODE_TMPDIR).
  • Changed: the chat agent skills check that a started worker came up, and correct their advice on Claude Code's read-only commands.

0.51.11 - 18 November 2026 - stable#

  • Fixed: doz chat set … --session NAME takes the name a Claude Code session shows, capitals and spaces included.

0.51.10 - 18 November 2026 - stable#

  • Added: chat writes each message straight into a Claude Code session's inbox on this Mac (sessions without a fence). doz chat who shows not running, idle or working.
  • Added: doz chat set NAME --deliver inbox|poll|webhook changes how a participant is reached, keeping its token, rooms and history; doz chat add NAME --inbox.
  • Added: dozchat is on your Mac's PATH, and reaches this Mac's chat server by default.
  • Fixed: the menu bar app restarts itself to update ("Restart to Update").
  • Changed: doz chat send lists each recipient once, with its latest state.

0.51.9 - 17 November 2026 - stable#

  • Added: dozchat, a small chat client in every sandbox and fenced session, with nothing to install and nothing to set. Its token is only ever a placeholder Dozable swaps.
  • Added: a static dozchat for x86_64 Linux on the release page, for agents outside Dozable.
  • Changed: the chat server's messages name Dozable's own commands.

0.51.8 - 17 November 2026 - stable#

  • Added: the chat protocol's documents, a one-file Python client and three agent skills, in docs/chat/ of the source repository, for agents that can install nothing.
  • Changed: an agent with a valid token can always ask which rooms it is in.

0.51.7 - 17 November 2026#

  • Added: in the Chat page, reactions, edit, delete, revealing a direct message, typing indicators and attachments (clip, paste or drop; up to 20 MB).
  • Added: serve.chat (off, read, write; default off) decides what your other browsers may do in chat.
  • Added: doz chat is listed in doz --help, with completions and a manual chapter.
  • Fixed: doz chat status, doz daemon status and doz doctor no longer report a new chat port before the chat server has moved to it.

0.51.6 - 17 November 2026#

  • Added: the Chat page in the dashboard, while chat is on: rooms, messages as they arrive, a composer with @ mentions, who is here, and unread counts.

0.51.5 - 17 November 2026 - stable#

  • Added: webhook bots (doz chat add NAME --webhook, doz chat webhook set|status|remove), with the entry kept in your login keychain.
  • Added: agents on other machines over Tailscale (chat.remote_listen, chat.remote_agents), as agents only.
  • Added: doz chat import COPY [--dry-run] [--add-missing] [--replace].
  • Fixed: a long answer from the chat server, such as doz chat read of a long room, was sometimes cut short.

0.51.4 - 17 November 2026 - stable#

  • Added: the daemon runs the chat server when chat.enabled is on (off by default), on this Mac only.
  • Added: the first doz chat commands: on, off, status, add, remove, who, token, rooms, room, send, read. You take part through a private socket and never have a token.
  • Fixed: a settings line under an old workspace.* name was warned about even after the new name was set.

0.51.3 - 17 November 2026 - stable#

  • Groundwork for chat (attachments and delivery into Claude Code sessions); nothing visible yet.

0.51.2 - 17 November 2026#

0.51.1 - 17 November 2026#

  • Added: doz account keepalive off|on|always. always renews this Mac's Claude login when it expires, with no sandbox needed.

0.50.3 - 16 November 2026 - stable#

0.50.2 - 16 November 2026 - stable#

Upgrade#

doz upgrade moves you to the newest version on your channel. With Homebrew directly, run brew update first, then brew upgrade dozable/tap/doz. Coming from 0.36 or earlier? Read the 0.37 post's Upgrade section first: 0.37 started with a new store.

There are three channels: stable (dozable/tap/doz), beta (dozable/tap/doz-beta) and canary (dozable/tap/doz-canary), which gets every build first. doz upgrade --channel canary switches.

More is coming soon. Thank you for using Dozable.
